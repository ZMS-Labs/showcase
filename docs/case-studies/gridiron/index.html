Gridiron · Game commentary

Record the play, then call it.

I wanted a broadcast companion for a football video game, Madden NFL 27, with commentary that follows what actually happened in the game. Gridiron is a research prototype built so each play is written into a record first, and the commentary is meant to work only from that record.

Separate what happened from what to say.

Commentary that runs ahead of the facts can celebrate a play that a flag has already wiped out, or call the same play twice. In Gridiron, the event reconciler (the part that works out what happened) writes each play to the ledger first. Only then does the producer, the part that decides whether to speak, get a turn.

In the sample drive on this page, the second play is a pass that draws a flag. It stays in the record as a voided play, a no-play, so the score remains 0 to 0 and nothing is said about it. The first play, a six-yard run, isn’t notable enough to call. The touchdown that ends the drive is the only play that gets a line.

For a score, the producer uses a fixed reaction line such as “Touchdown!”. Other lines are built from fixed templates filled with a packet of supporting facts, then checked by a claim guard, which rejects a line that names a player or a number those facts don’t support. When a language model is configured, it writes from the same facts; it does not decide what happened in the game.

A decision worth a closer look.

An unknown metric must remain unknown.

Before the snapshot was frozen, AI tools fixed the report so it no longer shows a value for anything that was never measured.

Constraint
A replay that repeats perfectly can make a report look convincing even when nobody has measured how well it reads the game screen or how accurate its commentary is.
Choice
Unmeasured values stay empty on purpose and carry a NOT_MEASURED label with a reason. A claim that the replay matched the answer key needs a complete answer key.
Tradeoff
The report makes fewer claims. It becomes clearer which conclusions a reviewer can and cannot draw.
Result
Four tests reject a report that claims accuracy nobody measured, that checks against a partial or missing answer key, or whose count of plays doesn’t match the key.

A source package you can download and rerun.

The download is the research snapshot itself. It holds:

  • a Python backend of 64 source files, covering window capture, reading the screen, the event record, the commentary producer, the claim guard and speech;
  • the bridge, a small read-only reader for save files;
  • a local dashboard with seven pages;
  • 20 generated data-format files, exported from the backend’s data models so every part uses the same shapes;
  • six design decision notes;
  • a research ledger that lists each candidate dependency, its license, and whether it was adopted or rejected.

It can demonstrate the replay without a game, real save, model account or model weights. With uv, Python 3.12 and Node.js installed, the quick start in its README reruns the replay.

A safety boundaries document rules out injecting code into the game, reading its memory, getting around anti-cheat and changing a save. The bridge’s read-only test fails if any of the known save-writing calls appears in its source.

The source package includes no game saves, captures, announcer recordings, model weights or private development history. Optional integrations have separate upstream terms.

What passed, and what remains open.

What is real here

On 19 September 2026 the replay ran twice from the command line on one made-up drive. No language model ran. The one line of commentary, “Touchdown!”, is the producer’s fixed reaction to a score, so the claim guard did not run in this replay; the archive’s tests check the guard on its own.

How accurately Gridiron reads a real game screen, and how accurate its commentary is, have not been measured. Live capture, compatibility with real saves, a complete played game, the optional language models, speech quality, latency and performance remain unverified.

The archive’s limitations file says what it would take to find out whether Gridiron holds up against a live game: a private set of at least 50 labeled plays to check how well it reads the screen, and one complete offline game, run and reviewed.
