Gridiron · Event reconciliation & grounded commentary

Make the event record
earn the commentary.

I wanted a broadcast companion whose commentary follows what happened in the game, so I put a reconciled event record at the center of Gridiron. This research application separates observations, confirmed events and supporting facts from the language produced from them.

What went into this work.

Project direction
I set the direction around an event record that commentary can rely on. For this public example, I chose a reproducible replay with clear limits on what it measures.
Construction and assistance
AI-assisted implementation and preparation, using existing backend, bridge and web components. The source archive retains its GPL declarations and third-party notices; it does not imply authorship of upstream integrations.

Separate what happened from what to say.

Ambiguous or changing observations can produce duplicate, premature or incorrect commentary. Gridiron's architecture places an event reconciler and a canonical ledger before the producer and language path.

The synthetic replay uses a deterministic text provider. Packets of supporting facts and a claim guard constrain that path; the language model does not decide the game state. Optional capture, save and speech integrations have their own validation requirements.

Repeatability, separate from accuracy.

Two runs produced the same canonical event-ledger hash. The observed event statuses and count matched the full synthetic oracle, with no play confirmed twice.

During preparation, I changed report values that had not actually been measured to explicit null values with NOT_MEASURED labels. A stable replay cannot establish perception accuracy or factual-error rates in commentary.

Four regression cases reject unsupported accuracy claims, partial event oracles, absent oracles and mismatched event counts.

A decision worth examining.

An unknown metric must remain unknown.

Constraint
A repeatable fixture can make a report look convincing even when perception and commentary accuracy have never been measured.
Choice
Represent unmeasured values as null with explicit NOT_MEASURED labels. Require a complete event oracle before accepting an oracle-match claim.
Tradeoff
The report makes fewer claims. It becomes clearer which conclusions a reviewer can and cannot draw.
Result
Four regression cases reject unsupported accuracy claims and incomplete or mismatched oracles. Repeatability remains a useful, separate observation.

Read one replay carefully.

An annotation of the synthetic fixture oracle paired with its recorded matching replay. The steps follow fixture order; they are not a live telemetry timeline.

01 · Confirm the first event.

The synthetic drive begins with a run for positive yardage. Its terminal event is confirmed.

p1 · CONFIRMED

The full oracle expects this status. The recorded run reports that all three terminal statuses match the fixture oracle.

02 · Preserve the voided play.

The next play is flagged as a no-play. It must not survive as a scoring event.

p2 · VOIDED

A voided record explains why an apparent play should not change the score. It is not silently converted into a confirmed event.

03 · Confirm the score.

The fixture then contains a confirmed touchdown. The deterministic text path produces one utterance across the fixture.

p3 · CONFIRMED

The saved output includes “Touchdown!” This is a fixture-level result; the annotation does not invent per-event timing or extra commentary.

Two runs produce the same canonical event-ledger hash with no duplicate commitments.
