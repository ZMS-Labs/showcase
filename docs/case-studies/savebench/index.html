SaveBench · AI factory design

Can an AI build a factory that actually runs?

SaveBench asks whether an AI can build a working factory in the game Satisfactory, by the game's own rules, with the running game as the judge. It began with AI models designing factories that the game then measured. A factory that only works on paper doesn't count.

    1. 0:00: SaveBench. Can an AI build a working factory in Satisfactory, by the game's own rules? This is where it stands on November 17, 2026.
    2. 0:06: The first milestone. Start in a blank world and earn milestone 1-1. It costs 100 Iron Plate, 100 Iron Rod and 200 Concrete. It must be done the way a player does it: ore comes from miners on the map's ore nodes, parts move between machines by belt, and hands are only for getting started. The game is the judge: the milestone counts when the live game accepts the payment and launches it. Script is a reference run, a fixed list of steps we wrote, and it is not an AI. Two AI models have tried, each choosing every step by itself: deepseek-v4-flash on a budget of one dollar a day, and Claude Opus 5.5 on eight dollars a day.
    3. 0:20: The script run, run BL, November 14, shown as a diagram that is not to scale. The script clears the rock on an iron node by hand and builds a Miner Mk1 on it, powered by a Biomass Burner. The Constructor then switches to Iron Rod, and 202 arrive, where 200 were wanted. A second line starts at a Miner Mk1 on a stone node. The game refuses a belt that is too long, so the stone passes through four containers before a Constructor turns it into Concrete: 203, where 200 were wanted. No part was moved by hand between machines. In this run the burner was still refuelled by hand; that gap closed on November 16. The finished Concrete is carried to the bank once, to pay. The game accepts the payment and launches milestone 1-1. 59 checks of 59 passed. This is a script run, not an AI.
    4. 0:46: The second script run, run BP, November 16, shown as a diagram. Milestone 1-2 costs 150 Iron Plate, 150 Iron Rod and 300 Wire. The script builds a copper line first, at a copper node 268 metres from the bank: a Miner Mk1, a Smelter and a Constructor making Wire. The first 48 Wire are carried to the bank to pay for the iron line, a declared carry. The iron line runs into the bank by belt: 196 Iron Plate where 190 were wanted, then 170 Iron Rod where 170 were wanted. The copper line gets its container and 304 Wire arrive in it by belt, where 300 were wanted. The finished Wire is carried to the bank once, to pay. The game accepts the payment and launches milestone 1-2. 52 checks of 52 passed. In a separate run the same evening, a burner ran on fuel fed by belt with no hand refuel.

DeepSeek cleared the rock and built a Miner Mk1, a Smelter, a Constructor, storage, a Biomass Burner and two belts, and wired the burner to the miner. It had spent all its Iron Rod. The last belt was refused because it cost 16 Iron Plate and the bank held 1. Power poles also cost Iron Rod, so the Smelter and Constructor never got power; for the poles this is inferred. Our harness told the model only that the placement was refused, so it spent 15 of its 34 replies looking for clear ground. The run stopped at its budget of 95 cents and the milestone was not earned. The fault was in our harness, not in how the model played. The fix was live for run 5 on November 16. It looked up an iron node, cleared the rock by hand, and built a Biomass Burner, a Miner Mk1, a Smelter and a Constructor, joined by belts. It tried to belt the Constructor to the bank and was refused, because our tool list did not offer the bank as a belt target, so it built a storage box. It ran power to a stone node and built a second Miner Mk1, a second Constructor and a second storage box for Concrete. Machines made everything the milestone costs: 128 Iron Plate where 100 were needed, then 184 Iron Rod where 100 were needed after it switched the Constructor, and 248 Concrete where 200 were needed. No machine was fed by hand. The declared hand steps were clearing the two nodes, 200 biomass for the burner, and collecting the finished parts from storage to pay. The game accepted the payment and launched milestone 1-1, after 10 replies and 35 cents. This is one run and has not been repeated yet.

Experiment · Sept 9, 2026

Before you judge the factory, check the ruler.

An AI agent designed a copper and concrete factory from the challenge alone: 34 buildings, 15 belts and 7 power lines. Nobody changed it afterward. Then the game measured it.

  1. Trial 1

    Test the measuring tool first.

    Every trial starts with a control: a sample factory with a known answer. This one should have delivered both products. It showed zero copper and zero concrete in each of two 61-second windows.

    That meant the measuring tool was broken, so the AI's factory was never judged. A missing measurement isn't scored as zero production.

  2. Find the fault, then prove the fix.

    The part that writes a design into the game's save file filled in a storage filter the game leaves empty. Materials reached the belts, but the depot counted none. The fix writes the filter the way the game does.

    In the second trial the connected control delivered both products and a disconnected copy delivered nothing. Now the tool could see a delivery, and see when there wasn't one.

  3. Trial 2

    Measure the same design again.

    Same design, byte for byte, and the same rule, fixed in advance: at least 20 copper ingots and 15 concrete a minute in every two-minute window, after a three-minute warmup.

  4. Two of three windows missed. The FAIL stays.

    Copper missed the first window. None had reached the depot when measuring began, most likely because the first ingots were still on a long belt, but the record doesn't prove that. Concrete missed the third by a hair: 30 delivered where 30.25 were needed, because one concrete machine runs at exactly the target rate. A good later window doesn't cancel an earlier miss.

    The FAIL is specific and useful, so it stays on the record. Nobody loosened the target or combined the two trials into a score.

When the rules rewarded the wrong thing, I changed the test.

In a later campaign, an AI model earned the game's milestones by feeding machines by hand and never built a conveyor belt. At first I called that a flaw in the model. Then I decided SaveBench measures factory design, not whether an AI chooses to automate. So the test became a production quota the factory has to keep meeting while nobody touches it, an approach from the Factorio Learning Environment research benchmark.

  1. Sep 12, 2026

    A harder challenge: 120 copper ingots and 60 concrete a minute in every window, slow belts only. Every AI design failed, and those FAILs were kept.

  2. Sep 13, 2026

    The same targets with faster belts allowed. Designs by Claude Opus 4.7 and GPT-5.5 (as configured) passed every window. Claude's first pass came from revising its own design after a measured FAIL. Both also had FAILs, so this isn't a ranking.

  3. Sep 13 to 19

    A campaign in a persistent world, judged by milestones bought in the game. Claude Opus 4.7 (as its runtime reported) bought eight. While it did, the interface let it move items into and out of machines without spending game time.

  4. Sep 18, 2026

    I changed what SaveBench measures: a quota the factory must keep meeting through a hands-off period.

  5. Sep 22 to 23

    The first quota sessions: 30 wire a minute into a declared depot. No session has passed yet. Two were inconclusive because the factory wasn't left untouched long enough, and the instructions had left out the hands-off rule. The latest session states it, and had no result as of September 23.

  6. Nov 1, 2026

    I widened the goal. An AI agent should play the game and build the factory itself, by the game's own rules, starting from an empty world, and be watched and judged as it goes. The test became a ladder of the game's own milestones.

  7. Nov 12, 2026

    A script, not an AI, climbed the first stretch of that ladder from an empty world. Its factory made the parts for milestone 2-1 and for the Space Elevator, an Assembler made 50 Smart Plating, the game accepted the delivery and moved on to its next phase. Earlier attempts failed and were kept. The run declared three departures from normal play: a storage box for ore and ingots, 20 extra starting parts to pay for the box, and extra starting fuel. It shows the ladder can be climbed. It doesn't show that a model can climb it.

  8. Nov 12 to 17

    The first AI player tried the first rung, milestone 1-1. DeepSeek V4 Flash (as configured) played five recorded runs and earned none. In the fifth, 14 of its 30 replies held no move, 13 of them because the reply ran out of room while the model was still thinking. The run stopped when its daily budget was spent, with 41 iron ore collected by hand and nothing made by its machines.

  9. Nov 14, 2026

    A script earned milestone 1-1 the way a player does. Miners on an iron node and a stone node fed machines by belt: 324 Iron Plate, 202 Iron Rod and 203 Concrete arrived by belt, and no ore, ingot or part was moved by hand between machines. The game accepted the payment. All 59 of the run's checks passed. This is a script, not an AI.

  10. Nov 16, 2026

    The script earned milestone 1-2 the same way, with a copper line making 304 Wire by belt. All 52 checks passed. In a separate run a burner ran on fuel that reached it by belt, which closed the last regular hand step.

  11. Nov 16, 2026

    Late that evening, US Central time, one script run earned milestones 1-2 and 1-1 in a single world that started empty. All 142 checks passed. A further stage that tried to double the iron line stopped because the script had no Cable for the new power lines; it was not part of the verdict and is kept on the record.

  12. Nov 16, 2026

    An AI model earned a milestone for the first time, shortly before midnight US Central time (November 17 by UTC, the date the evidence file uses). Claude Opus 5.5 (as configured) started in an empty world and earned milestone 1-1 in 10 replies over about 24 minutes, for 35 cents. It chose every move. It put a Miner Mk1 on an iron node and another on a stone node, and built a Smelter, two Constructors, belts and two storage boxes. Those machines made 248 Concrete, 128 Iron Plate and 184 Iron Rod, more than the milestone costs, and nothing that paid for it was made by hand. Three steps were done by hand and are declared: clearing the loose rock off each node before placing a miner, fuelling the burner, and carrying the finished parts from the storage boxes to pay. The model first tried to run a belt straight to the payment point and the test's tools refused, which is a gap in the tools. It is one run and has not been repeated.

Same design, repaired tool

The factory design, its build list, the task and the targets were identical in both trials. The save-writing code, the contestant tools and the evaluator's recorded version all changed with the repair, so the contestant's save file was rebuilt. This is the same design measured again with a repaired tool, not a rerun of identical files. Apart from these, one record differs only in its creation time.

Why each window missed

When measuring began, no copper had reached the depot yet; the record says that fits copper still traveling the long belt route, but doesn't prove it. For concrete, the design used one machine, which makes exactly 15 a minute at normal speed, and this challenge had no way to speed a machine up. The next day, the same default warmup left three reference factories short in their first window, so challenges in SaveBench's library now set their own warmup. This FAIL was not rescored.

The designer

The agent started with a fresh context and only the challenge and the tools every contestant gets, and the record shows its design used only those. The coordinating agent wrote the designer's instructions for this early run instead of using a frozen set, so the result stands on its own. The designing model isn't named because the only record of it is private session data. Later model names carry their basis (as configured, or as the runtime reported) and were not independently confirmed.
