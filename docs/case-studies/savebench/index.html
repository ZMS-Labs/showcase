SaveBench · AI factory design

Can an AI build a factory that actually runs?

SaveBench asks whether an AI can build a working factory in the game Satisfactory, by the game's own rules, with the running game as the judge. It began with AI models designing factories that the game then measured. A factory that only works on paper doesn't count.

The game unlocks buildings in tiers, and each tier has numbered milestones: 1-1 is tier 1, milestone 1. You earn a milestone by handing in the parts it costs, and the game itself accepts the payment, so the game is the judge.

These factories work, but they are not laid out as a player would lay them out. The test's building tool put some machines on rocks and cliff faces, in places tens of metres above or below the machine next to them, and it did not tell the model the height it had built at. The game accepted the belts and they carried the parts. How the game judges it.

The game is the judge

A milestone counts only when the running game accepts the payment. Each run starts from an empty world.

Play like a player

Ore comes from miners, parts move between machines by belt, and hands are only for getting started. Hand steps are declared beside the result.

Misses stay on the record

A run that falls short is kept and shown, like GPT-6.1 Sol's try at milestone 1-3.

Scripts are labelled

A script, a fixed list of steps written in advance, is the reference run. It is never counted as an AI.

What went into this work.

What I did

I decide what each project is for and check what comes back. I want AI models to design factories and the game itself to judge them. The September 18 call on what SaveBench measures was mine.

What the AI did

AI tools write the code: the prototype's interface, the part that writes designs into save files, the evaluator and the tests. AI contestants designed the factories judged here. The save-file work uses Satisfactory Agent Tools by petehunt, a fork of GreyHak's sat_sav_parse, both GPL-3.0.
