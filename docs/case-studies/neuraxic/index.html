A fragment can find its place later.

I chose an idea-first workspace. A “loose leaf” is an unplaced element; a “tome” groups a universe. The Library holds tomes, while the Catalog also includes loose elements.

Open an element and it becomes the focus. Prose, claims and the neighborhood map are views of that same subject, so writing and world-building can stay connected. Lenses offer different ways to read its relationships.

An open proposal is something to consider. Canon is what the author has explicitly accepted. A detail appearing on screen does not make that decision for them.

A lamplit archive with meaningful signals.

Dark green surfaces, parchment-toned text and warm gold give the original interface the feel of a place to read and think. Its shelves and dossiers make a collection of story facts approachable.

The marks have specific meanings: an open seal is a proposal, solid gold is canon, and ember-colored findings draw attention to concerns. These are the retained product components and procedural covers, rendered with new fiction.

Where I want to take it.

The wider design distinguishes world truth, the events a story presents, and what characters or audiences believe. A character can be wrong while the author knows the answer.

Time and versions

When an event happens in the fiction differs from when the author records it. An alternate continuity starts from a chosen baseline.

Contradictions worth exploring

A broken rule might become a mystery, an exception or a revision. The author decides. A shared story structure could later support adaptations without silently changing the underlying world.

These are design ambitions. The navigation and focused tests do not establish complete detection, adaptation or story-generation workflows.

A tested boundary: what belongs in this version?

These separate backend tests ask what a version can see and what an author has accepted. New fictional details from Bellweather Reach explain the assertions: three steps about branching, then two about proposals and promotion. The diagrams are explanations, not a recorded authoring session.

Step 1 of 5

Record a starting detail.

The main continuity contains a claim: the beacon is lit. A query at this point can return that claim.

“Visible” answers what belongs in this query. The claim can still be a proposal; appearing in the result does not make it canon.

Give the what-if a parent baseline.

The author creates an alternate continuity. Neuraxic records where it branches from the parent’s history.

The branch can see parent claims up to that baseline. It does not need to treat every later parent edit as part of its own starting point.

Let the main story move on.

A later parent claim says the causeway is closed. Query both continuities at that later record point.

The main view includes the new claim. The alternate still sees the earlier beacon claim, and excludes the parent’s post-fork causeway claim.

Keep a conflict available for judgment.

A separate test starts with a canon claim, then records a different value for the same subject and predicate in the same continuity.

In this fictional explanation, “the beacon is unlit” conflicts with an existing canon claim that it is lit. Neuraxic reports the conflict and keeps the new claim as a proposal. It neither rejects the idea nor silently changes canon.

Record promotion as its own action.

For a selected proposal, an explicit promotion creates a canon receipt that records the actor. Repeating that promotion with the same key returns the same receipt.

The retry test also commits the first transaction and opens a new session before trying again. The receipt still identifies the same action.

Visibility and approval remain separate. The branch example concerns parent claims. Shared-library content follows separate update rules, so a fork should not be described as freezing every source the project can see.

What the rules cost the author.

A stable starting point needs deliberate updates.

A branch retains its parent baseline, so a useful later correction does not arrive automatically. No merge or rebase workflow is demonstrated here.

A conflict needs a decision.

Keeping a disputed proposal lets the author reconsider it. Detection and a promotion receipt cannot decide narrative quality or guarantee complete consistency.

How I’m developing it.

I direct the product and work through its design with AI assistance. Keeping exploratory ideas separate from author decisions is central to that direction.

The current interface and five existing tests show different parts of the work. They do not establish sole authorship of the components or tests, professional deployment, or a finished authoring product.

A small, reproducible boundary.

Five existing tests passed on 19 September 2026. Zero failures. Zero skips.

The selection ran real service and query functions against in-memory or isolated temporary SQLite databases. Network connections were disabled. No models, application services, private story material or generated prose were involved.

  • Record point: an earlier query excludes a later claim.
  • Parent baseline: a branch includes the earlier parent claim and excludes a post-fork parent claim that remains visible in the parent view.
  • Conflict: a different value is reported against existing canon while the new claim remains a proposal.
  • Promotion: the actor is recorded, and same-key retries return the same receipt both within a session and after a committed-session boundary.

What remains unproved

This selection does not establish PostgreSQL concurrency behavior, production authentication, deployment readiness, full application interactions, manuscript quality, or conflict resolution across every storyworld relationship.

The public diagrams use new fictional content to explain related test assertions. They are separate from the authentic interface captures and are not a replay of those fictional inputs through the application. Source, private world material and the full verification receipt remain private.
