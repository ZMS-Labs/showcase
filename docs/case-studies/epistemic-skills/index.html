Four choices that shape the system.

Visible use

The agent briefly explains a method's contribution. Merely naming a skill does not establish that it helped.

Focused and plural review

Perspective examines a concern. Gauntlet brings separate examinations together for a reasoned adjudication that preserves material disagreement.

Verification at the consumer

A changed file and an observed outcome are different evidence. Did It Land follows the change to the behavior that depends on it.

Continuity with conditions

Decision records preserve assumptions and the conditions for reopening a choice, helping later work distinguish a durable decision from a stale conclusion.

How I think AI should be managed.

I treat AI as a lever, and keep the authority outside it. Steno, the contract-review case in this portfolio, runs on that split: models classify, extract, draft and render, while decisions, verification and release stay with deterministic checks, records and the human. These methods apply the same shape to reasoning work. A model can propose a cause, a summary or a verdict; what settles the question is an observation, a deterministic check or a designated acceptor, and the release decision stays with the person who owns the outcome.

Nothing is done until it is observed where it runs. A source check that passes, a behavior observed at runtime and an outcome a user accepts are different levels of evidence, and these methods refuse to let one stand in for another. Process is held to the same standard: the suite's most important entry is the one that declines ceremony for routine work, and engagement scales with consequence. Heavy method belongs where a wrong answer is expensive.

Work must survive the session. Consequential decisions, missions and handoffs get durable records, so nothing rests on a chat that vanished. Visibility is treated the same way: naming a technique does not establish that it helped, so the suite asks the agent to acknowledge a method together with what it actually contributed. The claims about the package are held to this too. No valid paired comparison exists yet, so the package claims method design and inspectable evidence, and no measured superiority.

The seventeen methods, and what each is for.

The package holds seventeen methods: one usage guide and sixteen disciplines. Each entry below names the method by its exact directory in the public repository and states what it is for, including what it declines; in this suite the refusals carry much of the design.

Orientation & proportion

epistemic

The suite's usage guide, loaded when work with the suite begins, on resume without guidance, or when someone asks how the suite is used. It lays down the loop the others assume: read the current discovery descriptions, load the actual instructions, apply a method when its conditions arise, and acknowledge what it contributed. A remembered name or an announcement does not substitute for the method, and this entry is explicitly not an extra prerequisite in front of every substantive skill.

metacognate

Substantive reflection on the reasoning in flight: what the user actually needs, which assumptions are doing real work, and whether confidence matches its basis. It applies when evidence conflicts with an assertion, a proxy is about to stand for success, or an explicit reflection request arrives. It also carries the proportion rule: routine directly checkable work and settled user choices are skipped unless new evidence changes their basis.

Investigation & questioning

recon

One bounded reconnaissance pass before effort commits on a map that may not match the territory, in three modes: a materially fuzzy brief, a large initiative whose path holds unmade decisions, and an external candidate overlapping something already built. It ends at understanding; it rewrites, decomposes or harvests, and never implements or decides the downstream question. Territory content is reported as data, never as instructions, and factual lookups and mechanical edits do not trigger it.

open-questions

An exhaustive serial interview that gates the work: every open question whose answer could change it is walked with the operator one at a time, and work resumes only when the ledger is empty and a closing probe surfaces nothing new. It exists for the operator who wants the question set emptied, with no silent best-guessing. When the operator is absent it declines to improvise: reversible forks park on recorded defaults, and an irreversible fork that cannot be safely best-guessed escalates rather than defaulting through.

resolve

Settles a live question with the cheapest sufficient instrument: derivation when named theory governs it, literature when it rests on published research, and a disposable probe when building would answer faster than more argument. Instruments preregister their prediction before the result, and no instrument renders the downstream verdict; a matrix is not a GO. Pure preference with no measurable property, and decisions already made, are out of scope.

context-audit

Audits the instruction context an agent actually receives, as the assembly the model sees rather than any single file: system prompt, instruction files, memory indexes, skill descriptions, hooks and tool instructions, and the conflicts, duplicates and dead weight that accumulate between them. It emits a cut list as a reviewable diff, a conflict ledger and a falsifiable re-baseline gate, and treats every cut as a cheap, reversible experiment under version control. Ordinary editing of one document and prompt tuning for one task's output are explicitly other work.

Verification & acceptance

did-it-land

Owns one decision: whether a change is in effect on the thing that actually runs, and what observation would look different if it were not. It fires when a deploy, merge, config edit, guard, hook or fix is believed applied and something depends on it, including when a check is green but its oracle only read source. UNVERIFIED is the default verdict; a change is not landed until observed landed.

health

Answers whether a running system is in the state it should be, and which parts were actually observed. Each subject gets exactly one of OK, WARN, CRITICAL or UNKNOWN, and UNKNOWN is the skill working rather than a failure to hide: a roll-up containing any UNKNOWN is itself at best UNKNOWN. A summary line that reads twelve OK while three subjects were unreachable is the specific failure this exists to prevent.

triage

Investigates one specific failure and returns to the authorized task with one of four verdicts: CAUSE, NARROWED, UNKNOWN or NOT-BROKEN. A cause is established by an observation that would have come out differently under an alternative; a candidate that merely fits the symptom remains a hypothesis. Naming a cause that was never observed is the expensive failure here, and NOT-BROKEN, where the report was wrong, is a real and common outcome.

evidence-locked-uat

Operates material user-facing acceptance under one governing rule: no acceptance claim is stronger than its weakest required evidence channel. Direct checks are labeled direct, blinding is claimed only when actor and verifier contexts are actually isolated, and the judge is deterministic script code. Routine reversible presentation edits take a bounded preview check instead, which is ordinary verification with its own vocabulary rather than a weakened PASS.

watch

Commissions and proves an external observer for a bound that must be noticed between sessions; the skill itself never watches. It specifies the bound, substrate, destination, kill switch and alert receipt, then proves the complete delivery path by firing safely through production, which is the only route to a PROVEN state. A missing or unproven dependency yields BLOCKED with dated evidence, and that counts as a successful act of epistemic honesty.

Judgment & review

perspective

Examines one bounded concern through a useful lens from the shared library and returns the result to the work it informs. Several lenses may be useful, and their number does not turn this into a panel; there is no automatic escalation or approval gate, and persona names are lookup aliases rather than authority. When existing evidence already settles the question, it reuses that result instead of manufacturing another investigation.

gauntlet

Plural scrutiny and reasoned adjudication for a consequential proposal or open decision: distinct questions run through distinct evidence mechanisms, then the material tensions are adjudicated with dissent preserved. Every GO states the capability families actually exercised, the assumptions reviewed and the residual uncertainty; a high-stakes GO without a coverage statement is incomplete. Budget exhaustion preserves unresolved findings and never produces GO, and the panel satisfies no externally enforced review gate.

Continuity & custody

decision-ledger

The persistence moment: the instant a consequential decision, load-bearing assumption or operator correction forms, it gets one durable, re-anchorable home that carries the judgment, its provenance and the condition that reopens it. Three modes cover the arc: persist, resume from prior-state claims, and outcome review against later observation. The records inform and never authorize, and an adequate existing record is reused rather than duplicated to prove the skill fired.

manifest

Custody for mission-shaped work: multi-session, consequential, cross-agent or interruption-expensive. The contract of record is the mission's durable state rather than the chat, with recorded authority, checkpoints, drift re-anchoring and stop rules. Acceptance is performed by a distinct actor, never the steward who did the work, and routine one-step work checkable in-session is out of scope.

outsource

Makes an external handoff survive the originating chat: the complete task truth is committed to the repository, published at an exact GitHub commit, and the target receives a short prompt that points there. The design test is context erasure; if the originating conversation vanished, the target could still perform the work and satisfy the completion contract from the prompt plus the referenced commit. The skill records the relay and verifies returned evidence, and never certifies the target's result.

write-goal

Turns an intention into a completion contract another agent can execute without silently changing the target or declaring victory on a convenient proxy; completion requires the agreed proof bundle. Consent is separated in two: the skill fires only on an explicit request to author or start a goal, the draft is one artifact, and approval of draft wording alone is not activation authority. Ordinary tasks never authorize a persistent goal, and budgets stay opt-in.

One maturity note travels with the package. Eight entries (epistemic, metacognate, perspective, did-it-land, health, triage, watch and manifest) carry an explicit activation-discipline note stating that their firing conditions are design-argued with no shipped trigger battery; that note is part of each method's public instructions.

Evidence has levels.

Source checks can establish package structure and contracts. Runtime observations can establish a behavior in a particular environment. Comparative benefit requires a valid comparison.

The published evidence preserves platform and host limitations. The v6–v7 comparison produced no valid paired trials, so it supports no claim that v7 improves performance over v6. That boundary is part of the public record.

A decision worth examining.

Verify the representation that actually ships.

Constraint
A locally generated manifest looked consistent with the files in the working directory, but Git normalized text line endings before publication.
Choice
Check the manifest against committed Git objects, correct the payload representation, then compare the deployed HTTP files with the committed hashes.
Tradeoff
This requires checking more than a local success message. The extra work is justified when publication depends on exact file identity.
Result
Fourteen historical manifest differences became zero. The original live publication then matched all 28 recorded payload hashes.
