Four choices that shape the system.

Visible use

The agent briefly explains a method's contribution. Merely naming a skill does not establish that it helped.

Focused and plural review

Perspective examines a concern. Gauntlet brings separate examinations together for a reasoned adjudication that preserves material disagreement.

Verification at the consumer

A changed file and an observed outcome are different evidence. Did It Land follows the change to the behavior that depends on it.

Continuity with conditions

Decision records preserve assumptions and the conditions for reopening a choice, helping later work distinguish a durable decision from a stale conclusion.

Evidence has levels.

Source checks can establish package structure and contracts. Runtime observations can establish a behavior in a particular environment. Comparative benefit requires a valid comparison.

The published evidence preserves platform and host limitations. The v6–v7 comparison produced no valid paired trials, so it supports no claim that v7 improves performance over v6. That boundary is part of the public record.

A decision worth examining.

Verify the representation that actually ships.

Constraint
A locally generated manifest looked consistent with the files in the working directory, but Git normalized text line endings before publication.
Choice
Check the manifest against committed Git objects, correct the payload representation, then compare the deployed HTTP files with the committed hashes.
Tradeoff
This requires checking more than a local success message. The extra work is justified when publication depends on exact file identity.
Result
Fourteen historical manifest differences became zero. The original live publication then matched all 28 recorded payload hashes.

A real use: did the publication land?

A recorded task from this showcase's first full publication on 19 September 2026. The counts below are historical; this expanded site contains additional files.

01 · Question the local result.

Did It Land was applied to the publication boundary: whether the files being delivered were the intended ones.

14 differences in committed files

The original manifest described working-copy bytes. A check against the public Git objects exposed fourteen mismatches among 28 payload files.

02 · Identify the representation change.

The working copy included CRLF text. The repository already specified LF normalization for committed text.

Same content, different bytes

A local hash was not automatically a hash of the committed or delivered representation. This was an identity mismatch, not evidence of missing product functionality.

03 · Correct and reproduce.

The corrected publication described the normalized payload. The included script reconstructs both historical checks directly from public Git objects.

14 before → 0 after

Run python scripts/replay_manifest_case.py in a full clone of the Showcase repository. Python and Git are sufficient; no model or network call is made by the script.

04 · Check the actual destination.

After deployment, all 28 payload files were fetched from the public site and compared with the committed hashes.

28 historical HTTP payloads matched

This is one observed task. It does not isolate the skill's causal benefit or establish a general improvement in agent performance.
