Case study · Writing story worlds

Neuraxic

The app’s library screen

Try another version without losing the first.

I wanted a story’s prose, people, places and rules to develop together without losing what I’d already decided. Five tests passed: two check which details a version of the story includes, as of an earlier point and after a what-if version splits off, one checks that a conflicting detail stays a proposal, and two check that accepting a detail is recorded once, even if the request is sent twice.

Case study · Character design

Krewcible

After the changes · made-up choices

Take back one choice without losing the rest.

I want to shape a character out of choices I can see, change and take back before anything is generated. In a 36-second recording of the editor, the list goes from four choices to eight, one comes off along the way, and the written description follows each change.

Case study · Game commentary

Gridiron

Record the play, then call it.

A commentator who runs ahead of the facts can celebrate a play that a flag has already wiped out. Gridiron is a commentary system for a football video game, built so each play is written into a record first, and the commentary is meant to work only from that record. Two recorded runs of one made-up drive produced the same record, and the research source is a free download with a replay you can rerun.

Public source ·research prototype; not yet tested against the real game; no AI model ran

Case study · Characters and memory

Enaction

A character you play should not rewrite you.

The goal is to keep you separate from the character you choose to play. Its tests check that you can speak only as a character in the scene, and that a turn’s memories go to that character, not to you.

Case study · A shared service for generated files

Poiesis

Which file came back, and how long should it stay?

I wanted several apps to share one service for generating text and images, with clear rules about which file came back and how long it stays available. Its tests cover how a returned file is identified, when it expires and what happens to the stored prompt once a job finishes.

Public fork · a personal AI assistant

OpenClaw

OpenClaw is a personal AI assistant you run on your own devices. I want a way to talk to and choose between any of the AI models I use, and I expect to do that through OpenClaw. My fork’s main branch, the version anyone gets by default, changes none of OpenClaw’s code. It adds instructions for AI agents, a note of the OpenClaw version it’s based on and how updates get reviewed, and one automated check, which doesn’t run because automation is switched off on the fork.

AI tools wrote a pull request, a proposed change to the code, that adds three memory tools, with tests for two of them and an off switch for one. With them, another program can add to, remove from and consolidate what OpenClaw remembers. The pull request’s description notes that one tool can stall. A later comment reports the stall fixed in a test with made-up documents, and I’m keeping it unmerged until the fix works on a real memory store that already holds documents.
